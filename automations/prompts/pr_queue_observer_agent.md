## 1. Holistic 5-Agent Code Review & PR Queue Prioritization

### Pre-Queue Code Deprecation & Supersession Sweep (Mandatory)
Before ranking candidate branches, the observer MUST evaluate deprecation and supersession across all feature branches:
1. **Ahead==0 Merge Proof vs Zero-Commit Stubs (`GENUINELY_MERGED` vs `ZERO_COMMIT_ANCESTOR`)**: Because `is_ancestor(branch, main)` and `git diff main...<branch> == ""` are tautologically true whenever `ahead == 0`, NEVER label an `ahead == 0` branch `"Absorbed into main"` without merge proof (`pr_merge_<slug>_receipt.json` or second-parent merge commit on `main`). Clean `ZERO_COMMIT_ANCESTOR` branches (`dirty == False`, 0 stashes, no open waves) are recommended for `Decommission (No Value)` strictly as `"No unique commits vs main, abandoned zero-commit branch"`.
2. **Code Hunk Absorption & Untracked Worktree Diff Inspection**: For `ahead > 0` branches, if unique diff hunks are absorbed into `main` (`hunk_absorption_ratio >= 0.85`) or superseded by a `PACKAGE_READY` deliverable on `main`, recommend `Decommission (No Value)`. For `ahead == 0` worktrees, always inspect tracked and untracked (`??`) files on disk against `main` tree blobs (`get_target_tree_map`), diffing tracked worktree files against `HEAD` rather than `main` to prevent upstream commit inflation; never treat empty `git diff main -- <untracked_path>` stdout as hunk absorption. When `CANONICAL_MEETING_SUPERSEDED` is detected, it strictly covers deliverable paths (`output/`, `inputs/`), preserving any uncommitted code files as active residuals.
3. **Superseded Branch Tombstoning**: Flag branches whose deliverables have been superseded on `main` as `🚫 Superseded (Tombstone)` and exclude from active merge contention.
4. **Mandatory Dirty Gate & Anti-Overfitting Hazard Sweep**: If an `ahead == 0` branch has unabsorbed authored modifications or untracked deliverables in its worktree (regardless of `behind` count), NEVER decommission or prune blindly; recommend `[COMMIT_FIRST] ahead==0 but N uncommitted authored file(s); commit before prune` (or `Salvage Subset & Archive` when mixed with stale scratch code edits). Files deleted on `main` since fork point (`diff --diff-filter=D mb..main`) are classified in `stale_paths` and never salvaged. All committed and uncommitted hunks in `dual_pipeline/` are audited for anti-overfitting violations (prohibited meeting filenames, hardcoded meeting strings, or judge score tampering); any violation routes strictly to `ReviewVerdict.GOVERNANCE_BLOCK` (`Hold / Blocked`).

Every active candidate branch undergoes file-diff code review across 5 dimensions before determining priority rank, disposition, and action:
1. **Agent 1 — Per-File Hunk & Architecture Reviewer**: Inspect unified diff hunks (`git diff --unified=3 main...<branch>` for committed work, plus tracked `git diff HEAD` and untracked `??` worktree file hunks against `main` via `extract_file_hunks()` and `analyze_branch_file_diffs(..., worktree_path=...)`), L0–L6 import boundaries, 400-line module budgets, and code deprecation via `hunk_absorption_ratio` across production, test, and config hunks.
2. **Agent 2 — Business Value & Criterion Prioritizer**: Classify diffs under `config/pr_priority_rubric.json` (`COST_REDUCTION` > `LATENCY_IMPROVEMENT` > `GRAPH_INTEGRITY` > `FEATURE_AND_DELIVERABLE` > `HOUSEKEEPING`), labeled `MEASURED`, `EXPECTED`, or `UNVERIFIED`.
3. **Agent 3 — Git Topology & File-Overlap Analyst**: Compare `mb..branch` vs `mb..main` via `git merge-tree --write-tree` and `git cherry -v main <branch>`, separating `absorbed_files` ($\ge 85\%$ in `main`) from `salvageable_files` ($< 85\%$ in `main`).
4. **Agent 4 — Verification, Wave & Security Gatekeeper**: Verify E2E/adversarial coverage, open wave status, Class B receipts, and credential/egress safety.
5. **Agent 5 — Concrete Disposition, Completion Separation & Action Synthesizer (`verdict_verifier.py` & `completion_state.py`)**: Synthesize into the 5 canonical value dispositions (`Promote to Main`, `Complete In-Flight Work`, `Salvage Subset & Archive`, `Hold / Blocked`, `Decommission (No Value)`), 3 explicit completion states (`COMPLETED`, `IN_PROGRESS`, `DECOMMISSION` via `evaluate_branch_completion_state()`), and 7 `ReviewVerdict` values (`MERGE_READY`, `REVIEW_READY`, `RESOLVE_CONFLICTS`, `REBASE_RETARGET`, `GOVERNANCE_BLOCK`, `SPLIT_REQUIRED`, `SUPERSEDED_TOMBSTONE`) using deterministic file-diff proof (`verify_branch_verdict_and_disposition()`):
   - **Deterministic Completed vs. In-Progress Separation (`completion_state.py`)**: Within every priority tier (`P0`–`P3`), `COMPLETED` branches (`Code Completed? = Y`, `ahead > 0`, `dirty == False`, zero git locks, zero active worktree PIDs, `open_waves == "—"`) strictly sort ahead of `IN_PROGRESS` branches (`Code Completed? = N`, dirty files, open waves, active git locks/PIDs, or `ahead == 0` uncommitted work). Every `Immediate Blocker / Action` string is prefixed with `[COMPLETED — READY]` or `[IN PROGRESS — <reasons>]`, and `decisions.json` / `reports/pr_queue_detail.json` partition `completed_branches`, `in_progress_branches`, and `decommission_branches`.
   - **`Promote to Main`** (`MERGE_READY` / `REVIEW_READY` / `RESOLVE_CONFLICTS`): Requires `ahead > 0`, `dirty == False`, `open_waves == "—"`, and `len(salvageable_files) > 0` (`hunk_absorption_ratio < 0.85`).
   - **`Complete In-Flight Work`** (`REVIEW_READY` / `COMMIT_FIRST` / `CONTINUE_WAVES`): Requires active unabsorbed work (`dirty == True` with `len(absorbed_files) == 0` or `open_waves != "—"`).
   - **`Salvage Subset & Archive`** (`REVIEW_READY` / `[HITL_CLARIFICATION_REQUIRED]`): Triggered when file-diff inspection proves partial absorption (`len(absorbed_files) > 0` and `len(salvageable_files) > 0`, or `0.25 <= hunk_absorption_ratio < 0.85`).
   - **`Hold / Blocked`** (`GOVERNANCE_BLOCK` / `SPLIT_REQUIRED` / `REBASE_RETARGET`): Triggered when governance hazards, mass-reformat >300-file commits, or deleted/archived stale paths on `main` block promotion.
   - **`Decommission (No Value)`** (`SUPERSEDED_TOMBSTONE` / `PRUNE`): Requires either 100% file/hunk absorption (`len(absorbed_files) > 0` and `len(salvageable_files) == 0`, or `hunk_absorption_ratio >= 0.85`), a `PACKAGE_READY` deliverable superseder on `main`, or a clean `ahead == 0` zero-commit ancestor (`dirty == False`, 0 stashes, `open_waves == "—"`). Zero-unabsorbed branches (`abs_cnt > 0 and unabs_cnt == 0`) must NEVER be overridden to partial salvage.
   - **Mandatory HITL Clarification Gate (`needs_operator_decision(c_top, c_second)`)**: Every branch disposition is scored with calibrated top-two candidate confidences `(c_top, c_second)` and margin $\Delta = c_{\text{top}} - c_{\text{second}}$. Whenever $\Delta \le 0.20$, $c_{\text{top}} < 0.70$, or partial absorption mixes absorbed and unabsorbed files, `verdict_verifier.py` marks `requires_hitl_clarification = True`, prefixes the action with `[HITL_CLARIFICATION_REQUIRED]`, and generates a plain-English `hitl_question_payload` so the operator is queried via atomic `ask_user_question` before any destructive or ambiguous action is taken.

## 3. Worktree & Git Stash Coverage & Interactive Cleanup Follow-Up (`Scope C` / `Gate G5` / `worktree_coverage_cleanup`)
1. **Pre-Flight Worktree & Stash Inventory (`INV-WT-COVERAGE`)**:
   - Run `python tools/pr_governance.py inventory --json` to enumerate all `.worktrees/` entries and git stashes under `INV-WT-COVERAGE`, writing coverage output to `reports/worktree_coverage/coverage_<MM-DD-YYYY>.json`.
   - Classify worktrees into:
     - `ORPHAN_DELIVERABLES`: Worktrees containing uncommitted meeting deliverables (`01_*`, `output/**`, transcripts, audio) protected under the `Zero Data Loss Invariant`.
     - `EMPTY_STUB`, `MERGED_BRANCH`, or `COMPLETED_INGESTION_WORKTREE`: Candidates for token-bound pruning via `python tools/pr_governance.py finish <branch> --ingest` with an explicit, cryptographically verifiable `--confirm-token`.
2. **Scheduled Mode Read-Only Coverage Reporting (`MODE: scheduled`)**:
   - Write coverage output to `reports/worktree_coverage/coverage_<MM-DD-YYYY>.json` alongside the queue snapshot. If worktrees have `ORPHAN_DELIVERABLES`, do NOT prune; highlight orphans and record `OPERATOR_INPUT_REQUIRED`.
3. **Interactive Mode 20% SSOT Margin-Gated Decision & Recovery Follow-Up (`Gate G5` — Priority Tier `W`)**:
   - After rendering the read-only 10-column PR queue table in `MODE: interactive`, if interactive worktree/stash cleanup is invoked for items in priority tier `W`, calibrate option confidences via `calibrate_options` and evaluate `needs_operator_decision(c_top, c_second)`:
     - If `ORPHAN_DELIVERABLES`: Recover to a dedicated branch `feat/<slug>` and register the worktree via `AUTONOMOUS` receipt in `hitl_decision_ledger.json` when calibrated spread $\Delta > 20\%$ (`[Confidence: HIGH (95%)]` vs `[Confidence: MEDIUM (60%)]`), or present atomic recovery options via `ask_user_question` when $\Delta \le 20\%$ and record choice in `hitl_decision_ledger.json`.
     - If `EMPTY_STUB`, `MERGED_BRANCH`, or `COMPLETED_INGESTION_WORKTREE`: Obtain confirm token via `python tools/pr_governance.py inventory --json`; when calibrated spread $\Delta > 20\%$ (`[Confidence: HIGH (98%)]` vs `[Confidence: MEDIUM (60%)]`), execute token-bound pruning via `python tools/pr_governance.py finish <branch> --ingest` with `--confirm-token` and record an `AUTONOMOUS` receipt in `hitl_decision_ledger.json` (or prompt via `ask_user_question` only when $\Delta \le 20\%$). Re-run `python tools/pr_governance.py inventory --json` to verify clean state and emit the `Worktree & Stash Coverage Status` and `Wave Implementation Status Table` in the coverage report.

4. **Three-Step Git Commit, Rebase & Governed PR Merge Lifecycle (`automations/prompts/_shared_governance_contract.md` §3.4)**:
  1. Commit declared wave deliverables, Wave Implementation Status Table, and `docs/plans/<branch-slug>.md` on the isolated feature worktree branch.
  2. Rebase onto local `main` via `.venv/bin/python tools/pr_governance.py rebase <branch>`.
  3. Present `PR_MERGE_AUTHORIZATION` and merge into local `main` via `.venv/bin/python tools/pr_governance.py review <branch> --fail-fast` and `.venv/bin/python tools/pr_governance.py submit <branch>` (`tools/pr_governance.py merge <branch>`).
